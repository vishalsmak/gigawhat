How GigaWhat works

GigaWhat helps gas and electricity staff find the approved procedure for the job, see the evidence behind it, and get suggested next steps. People make the decisions. It never decides anything safety-critical, and it has no connection to the plant.

Setting
Fictional UK multi-utility, gas and electricity
Users
Field engineers, control room, Authorised Persons, auditors
Data
Public HSE guidance plus fictional procedures and records
Status
Built and tested; ready to deploy once API keys are added

What it will and won't do

Will

  • Find the approved, current procedure for this asset, site and role
  • Summarise evidence from procedures, the document register, incidents, work orders, inspections and alarms, citing every claim
  • Suggest next steps, each tied to a source
  • Send safety-critical work to an Authorised Person for approval

Won't

  • Connect to or operate SCADA, switching or valves
  • Write its own steps for safety-critical work; it quotes the procedure instead
  • Use draft, withdrawn or superseded documents
  • Guess when evidence is thin; it says so and points to an Authorised Person or the document controller

The standard RAG pipeline this builds on

Retrieval-augmented generation (RAG) means finding the relevant passages first and giving them to the model alongside the question, so it answers from your documents rather than from memory. The major references describe the same shape, even when their stage names differ: an indexing pipeline that runs when documents change, a query pipeline that runs for every question, and a few concerns that span both. This is the reference GigaWhat is built against. The table below the diagram shows where GigaWhat follows the standard and where it adds to it.

In short, GigaWhat is a standard pipeline plus three additions that come from the safety domain: routing by safety tier, verbatim quoting for safety-critical work, and human approval. The references cover routing in general, but none has safety tiers, verbatim-only answers or a human sign-off step, so these are the parts worth explaining to a reviewer.

Naive, advanced and modular RAG

The most cited survey of the field (Gao et al.) sorts RAG systems into three generations. The terms are common in interviews and papers.

Naive RAG

  • "Retrieve-read": index, take the top k chunks from one vector search, paste them into the prompt
  • The usual first tutorial; weak on exact terms, permissions and thin evidence

Advanced RAG

  • Adds pre-retrieval steps: better chunking, metadata, query rewriting, hybrid search
  • Adds post-retrieval steps: reranking and trimming the context

Modular RAG · GigaWhat

  • Steps become swappable modules (routing, fusion, memory) wired into patterns such as rewrite-retrieve-read or adaptive retrieval
  • GigaWhat: advanced retrieval inside a routed LangGraph workflow

How retrieval works

Loading documents

  1. Parse with Docling. It keeps headings, numbered steps, tables and WARNING/CAUTION boxes as structure instead of flattening them to text.
  2. Chunk by section. A step is never separated from the warning that goes with it, and every small chunk links to its parent section, so the model sees the whole sequence of steps.
  3. Add a context header. Each chunk carries its breadcrumb (document, version and section) before it is embedded, so a chunk that only says "apply locks" still knows which procedure and section it belongs to.
  4. Version in one transaction. Loading v4 of a procedure marks v3 as superseded at the same moment. v3 stays available for audit questions such as "what did it say on 3 March?"
PR-GAS-031 v3 · Approved · effective 2026-04-01 › 6 Purging › 6.2 Nitrogen purge of PE mains
WARNING  Do not vent purge gas within 5 m of an ignition source.
6.2.4  Confirm the main is isolated at both ends and the isolation is recorded on the permit.
6.2.5  Connect the nitrogen supply through the purge saddle and open slowly ...

A fictional chunk as stored. The header in teal is what makes it findable, and the warning travels with its step.

People and permissions

Visitors pick a persona when they arrive, using Chainlit's chat profiles. No sign-up is needed. A random browser ID keeps each visitor's chats and approvals separate. A persona can't approve its own request, so to see both sides, ask as an engineer and then switch to the Authorised Person.

For a real deployment, the persona picker would be replaced by single sign-on, with roles and business units coming from identity-provider groups (for example Cognito). This demo doesn't include that, and separation of duties compares personas rather than people.

How this maps to production

GigaWhat is built from open-source parts. Companies that run this kind of assistant for real usually build it in one of three ways: assemble it themselves, as GigaWhat does; use their cloud provider's managed RAG services; or build on the data platform where their data already lives, most often Databricks. Each stage of the pipeline exists in all three. What changes is who runs each stage.

Assemble it yourself (GigaWhat)

  • Pick when permissions, document versions and exact wording must stay under your control
  • Runs anywhere, including offline on a laptop
  • Cost: you write and run more of the code yourself

AWS managed

  • Pick when the company already runs on AWS and wants fewer moving parts to operate
  • Parsing, chunking, syncing and hybrid search come ready-made
  • Cost: who-sees-what is only as safe as the filter code in the app

Databricks

  • Pick when asset registers, work orders and sensor history already live in Databricks
  • One catalog for permissions and lineage across data and AI
  • Cost: a whole platform with its own bill; heavy for a small demo

GigaWhat stays on the first stack. Three details are worth knowing when reading other material:

  • Bedrock's newer Managed Knowledge Base can filter results by each user's access list, copied from sources such as SharePoint or Confluence. It uses AWS-managed storage rather than Aurora, and AWS describes it as filtering, not a security boundary.
  • Databricks renamed Vector Search to AI Search in June 2026, and replaced AI Gateway with Unity Gateway in August 2026. Most tutorials still use the old names.
  • If the project Region is eu-north-1: Knowledge Bases, Guardrails, AgentCore and Bedrock evaluations are offered there, but Bedrock's Rerank API is not, so an AWS-managed version would keep reranking in the app.

Before deployment

  1. Confirm the AWS project Region (the local config says eu-north-1, Stockholm)
  2. Upgrade the AWS project to the Paid plan before 9 April 2027, when the Free plan ends and the project would close
  3. Choose the address for the shared link: the free sslip.io hostname Terraform outputs, or a purchased domain
  4. Add the Anthropic and Cohere API keys to SSM Parameter Store, then follow infra/README.md
