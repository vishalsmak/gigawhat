## How to read this log

- **Controls** name the mechanism and the file that implements it. Paths are relative to the repository root.
- **Verification** names the test function (`file::test`) or the evaluation release gate that shows the control works. "None" means nothing automated proves it today.
- **Residual risk** is a qualitative judgement for a deployment that keeps today's design but adds named owners and real sign-on: **Low** (controls are enforced by code or the database and tested), **Medium** (controls depend on a model or a person, or have known gaps), **High** (the control is weak or missing for real use). Where the demo and real use differ, the cell says so.
- Release gates are defined in `src/gigawhat/evaluation/report.py` and explained in [evaluation-report.md](evaluation-report.md).

## Open actions

The highest-priority items for any real use are H10 and H18, which both come down to the missing sign-on, and H15, the database login that can bypass the audit trigger. [README.md](README.md) lists the main open gaps across the pack.

Review this log whenever a change touches the safety-tier rules, prompts, models, retrieval thresholds, access control, approvals or the audit trail ([change-control.md](change-control.md)).
